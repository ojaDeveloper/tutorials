起点 · 域名解决的根本问题

第 0 章：域名到底是什么？

一句话：给冷冰冰的服务器地址，起一个人能记住的名字

互联网上每台服务器，真正的"门牌号"是一串数字，叫 IP 地址，比如 93.184.216.34。电脑之间靠 IP 互相找到对方。但问题来了：

核心难题：没人记得住一堆 IP 数字。你能记住 142.250.72.14 是谁吗？但你记得住 google.com。IP 是给机器用的，人需要一个好记的名字。
域名就是这个"好记的名字"：example.com 是贴在 IP 93.184.216.34 上的一张便签。你输入域名，系统在背后帮你把它翻译成 IP，再去连接。
打个比方：域名像"张三"这个名字，IP 像他的手机号。你存通讯录时记"张三"，拨号时手机自动翻出号码去拨。域名系统，就是整个互联网的通讯录。
验证方法 · 亲眼看到"域名背后是个 IP"
  1. 打开终端（Windows 用 Git Bash / PowerShell / CMD），敲 ping example.com。
  2. 看输出：域名旁边会显示一串 IP 数字（如 [93.184.216.34]）——这就是它翻译出来的真实门牌号。
  3. 再 ping baidu.com，换一个域名，IP 也换了。证明每个域名都对应着某个（或某些）IP。
验证到了什么：你输入的域名，最终都被翻译成一个 IP 才能连上——名字是给你看的，机器认的是数字。
结构 · 一个网址是怎么组成的

第 1 章：拆开一个网址，每一段都有名字

看懂结构，后面 DNS 的"接力"才好理解

以 https://www.example.com 为例，域名部分要从右往左读，因为越右边"级别越高"：

https://www.example.com（.）
协议　　子域名　主域名　顶级域　(隐藏的根)
🧩 从右往左，一层层拆
根 .
最顶层，平时省略不写（末尾那个隐藏的点）。全世界所有域名都挂在这个"根"下面。
顶级域 TLD
就是 .com .cn .org .net .io 这些。Top-Level Domain。分商业(.com)、国家(.cn/.jp)等。
主域名
example——这才是你花钱注册、真正属于你的那部分（连同它的 TLD，合称你的"域名"）。
子域名
www——你注册到主域名后，可以自己免费任意划分：www、blog、mail、shop 都行，指向不同地方。
协议 https://
严格说不属于域名，是"用什么方式通信"（见第 7 章）。/path 路径也不是域名的一部分。
关键领悟：你买 example.com，买的是主域名+顶级域这一整块。买到手后，前面的子域名（www、blog…）随你切分，不额外花钱。这就是为什么一个域名能开出无数个子站点。
验证方法 · 用一个真网址对号入座
  1. 看这个教程站的地址（假设是 用户名.github.io）：github.io 里 .io 是 TLD、github 是主域名、用户名 是子域名。
  2. 随便找 3 个你常用的网址，把每段对应到"子域名/主域名/顶级域"。你会发现 www 只是个可有可无的子域名——很多网站去掉 www 也能开。
验证到了什么：网址是分层的；你拥有的是主域名，子域名是你自己的地盘。
来源 · 域名从哪注册、谁在管

第 2 章：域名怎么注册？（以及它其实是"租"的）

搞懂管理体系，你才明白为什么要每年续费、去哪买

域名不能凭空占有，背后有一套三层管理体系，别被名字绕晕：

🏛 谁在管域名（三层）
ICANN
最顶层的国际管理机构，制定规则、管理根和 TLD 的分配。你不直接跟它打交道。
注册局 Registry
管理某个 TLD 的机构。比如 .com 由 Verisign 管，.cn 由 CNNIC 管。它维护该后缀下所有域名的总账本。
注册商 Registrar
你实际买域名的地方——面向消费者的零售商。如 Cloudflare、阿里云万网、腾讯云、GoDaddy、Namecheap。你付钱给它，它去注册局帮你登记。
重要真相：域名是"租"不是"买断"。 你注册域名是按年付费租用使用权（1 年起，可续多年）。到期不续费，域名会被释放，别人就能抢注。所以务必开自动续费，或记好到期日——很多人的网站挂掉就是忘了续费。

从 0 到 1 注册一个域名

  • 想名字：越短越好记越好；选后缀（个人站 .com/.io/.me 都行）。
  • 查是否可注册：在任意注册商网站搜索框输入想要的名字，它会告诉你"可注册"还是"已被占用"。
  • 下单付费：选年限，结算。常见 .com 一年几十到一百多块。
  • 实名认证：.cn 等国内后缀需实名（上传身份证）。国际后缀通常更快。
  • 拿到手：注册成功后，你就能在注册商后台管理它的 DNS 解析（第 3、6 章）。
验证方法 · 查一个域名的"户口本"
  1. 用 WHOIS 查询（搜"whois 查询"或用注册商的工具）输入任意域名，能看到注册商是谁、注册日期、到期日期（部分信息可能被隐私保护）。
  2. 命令行版：whois example.com（部分系统需安装）。看到 Registrar 和 Expiry Date 字段，印证"有注册商、有到期日=租用制"。
  3. 去任一注册商搜你的名字试试，感受"可注册/已占用"的即时反馈。
验证到了什么：每个域名都有注册商和到期日；它是有期限的租约，不是永久财产。
核心 · DNS 这本"通讯录"

第 3 章：DNS 是什么？（把名字翻译成 IP 的系统）

这是整篇的枢纽，务必吃透

DNSDomain Name System 域名系统 就是第 0 章说的那本全球通讯录：你给它一个域名，它还你一个 IP。但它不是一本存在某一台电脑里的书——它是分布在全球、层层分工的一套系统（第 4 章看它怎么接力）。

你在注册商后台给域名配的那些"解析记录"，就是往这本通讯录里写条目。常见记录类型：

记录类型大白话作用
A 记录把域名指向一个 IPv4 地址（如 93.184.216.34）。最常用。
AAAA 记录把域名指向一个 IPv6 地址（新一代更长的 IP）。
CNAME 记录把域名指向另一个域名（别名）。比如把 www.你的域名 指向 用户名.github.io——部署那篇就是这么绑的。
MX 记录指定收邮件的服务器。用你的域名发/收邮件时配它。
TXT 记录放一段文本，常用于"证明这域名是你的"（域名验证）、防伪邮件等。
NS 记录指定这个域名由哪些"权威服务器"负责解析（第 4 章的最后一棒）。
一句话记住区别：A = 指向数字 IP；CNAME = 指向另一个名字（让它再去解析）。个人建站你用得最多的就是这两个。
验证方法 · 亲手查一个域名的解析记录
  1. 终端敲 nslookup example.com，返回它的 A 记录 IP。
  2. 查 CNAME：nslookup -type=cname www.github.com（换成有 CNAME 的域名），看到它指向另一个域名。
  3. 进阶用 dig example.com（Mac/Linux/Git Bash 自带），输出里 ANSWER SECTION 就是解析结果。
验证到了什么：DNS 记录是真实可查的；A 给 IP、CNAME 给别名，一目了然。

第 4 章：按下回车后，到底发生了什么？

从敲下 example.com 到看见页面——一次完整旅程，逐步点给你看

这一步把前面所有概念（IP、域名、DNS、记录）全部串成一条线。先玩下面的动画，再看文字版：

动画 · 一次访问的接力旅程（点"下一步"，看数据包怎么一棒棒传下去）
点"下一步"开始这场接力。

文字版·完整 8 步（大白话）

  1. 先翻自己的小本本（缓存）：浏览器/电脑先看"我最近查过 example.com 吗？"查过就直接用记着的 IP，跳到第 6 步。省时间。
  2. 问"解析器"（递归 DNS）：没记录，就问一个专门帮你查的递归解析器（通常是你的宽带运营商，或你手动设的 8.8.8.8/1.1.1.1）。你只管问，它负责跑完整个流程。
  3. 解析器问根服务器：解析器先问根服务器".com 归谁管？"根不知道具体 IP，但知道该去问 .com 的管理者，于是把 .com 顶级域服务器的地址告诉解析器。
  4. 再问 .com 顶级域服务器：解析器接着问它"example.com 归谁管？"它也不存最终 IP，但知道 example.com 的权威服务器是谁（就是你在注册商配的 NS），把地址给回来。
  5. 最后问权威服务器：解析器问这个权威服务器"example.com 的 IP 是多少？"这台才是真正存着你配的 A 记录的地方，它回答：93.184.216.34。解析器把结果记下来（缓存）再交给你的浏览器。
  6. 拿到 IP，建立连接（TCP 握手）：浏览器有 IP 了，跟那台服务器握手三次建立一条可靠通道（"你在吗？"—"在，你在吗？"—"在，开始吧"）。
  7. 亮身份、加密（TLS 握手，https 才有）：如果是 https，双方交换证书、协商密钥，把通道加密，别人偷看也是乱码——这就是地址栏那把🔒（第 7 章）。
  8. 发请求、拿页面、渲染：浏览器发一句 HTTP 请求"把首页给我"，服务器回一份 HTML，浏览器再按需要去取 CSS/JS/图片，最后画成你看到的页面。旅程结束。
一句话总结这趟接力：缓存没有 → 找解析器 → 解析器依次问 根→顶级域→权威 三级，一级指路给下一级 → 拿到 IP → TCP 连上 → TLS 加密 → HTTP 要页面 → 渲染。前 5 步都是"把名字翻译成 IP"（DNS 的活），后 3 步才是"真正连上去拿东西"。
为什么要分这么多级？ 因为全世界域名太多，不可能存在一台机器里。分级 = 分工：根只管"哪个后缀找谁"，顶级域只管"这个后缀下哪个域名找谁"，权威才管"具体 IP"。层层甩锅，各管一段，才扛得住全球流量。
验证方法 · 亲眼看到这趟旅程的每一段
  1. 看 DNS 那几步：用 dig +trace example.com（Git Bash/Mac/Linux），它会把"问根→问 .com→问权威"整条链一行行打印出来——和上面第 3–5 步完全对应。
  2. 看后面连接那几步：浏览器按 F12 打开开发者工具 → Network（网络）标签 → 刷新页面 → 点第一个请求 → 看 Timing：里面有 DNS Lookup、Initial connection(TCP)、SSL(TLS)、Waiting(等服务器)、Content Download——八步几乎一一对上。
验证到了什么：这不是抽象比喻，dig +trace 和浏览器 Timing 面板让你逐段看到真实发生的接力。
机制细节 · 缓存与"为什么要等"

第 5 章：缓存、TTL，和"改了 DNS 为啥不立刻生效"

这解释了新手最困惑的一件事：明明改对了，怎么没反应

第 4 章每一级查完都会把结果记一段时间（缓存），这样下次同样的查询就不用再跑全程，快得多。记多久？由一个值决定：

TTL（Time To Live，存活时间）：每条 DNS 记录都带一个 TTL，比如 600 秒。意思是"这条结果可以放心用 600 秒，过期再来问我"。TTL 越大缓存越久（访问快、但改动慢生效）；越小越灵活（改动快生效、但查询更频繁）。
这就解释了那个经典困惑：你在注册商把 A 记录从旧 IP 改成新 IP，但访问还是旧的。因为全世界的解析器、你的电脑、浏览器里，旧记录还在缓存里没到期。得等 TTL 过期，新记录才铺开。这个铺开过程叫 DNS 传播，可能几分钟到几十小时。不是你配错了，是缓存还没散。
实用技巧：打算改 DNS 前，提前把 TTL 调小（如 300 秒），等改动稳定后再调回大值。改完想让本机立刻重查，可清本地 DNS 缓存：Windows ipconfig /flushdns，Mac sudo killall -HUP mDNSResponder。
验证方法 · 看到缓存和 TTL 真实存在
  1. dig example.com 看 ANSWER 里那个数字（如 3600）就是 TTL。连续再查一次，你会看到这个数字在变小——它在倒计时，说明你拿的是缓存、正在过期。
  2. 换个"全球 DNS 检测"网站（搜 "dns checker"），输入一个域名，能看到不同国家/地区解析出的结果——直观感受"传播"是逐地铺开的。
  3. Windows 敲 ipconfig /displaydns 看本机缓存里存了哪些域名。
验证到了什么：缓存和 TTL 是真的，改 DNS 要等是缓存机制的必然，不是故障。
接上你的网站 · 和部署那篇合体

第 6 章：把你买的域名，指向你的网站

现在把"域名"和"部署"两篇彻底连起来

你在部署那篇拿到了 用户名.github.io/my-site/ 这种网址。现在想让 www.你的域名.com 打开同一个站。做的事就一句话：在域名的 DNS 里加一条记录，把它指向托管平台。

🔗 两种常见指向方式
指向 GitHub Pages
子域名（www）：加一条 CNAME，把 www 指向 用户名.github.io。
根域名（不带 www）：加 GitHub 给的几个 A 记录（指向它的 IP）。再在仓库 Settings→Pages 填上自定义域名。
指向 Cloudflare Pages
如果域名本来就托管在 Cloudflare，直接在 Pages 项目里"添加自定义域名"，它自动配好记录。否则加 CNAME 指向 项目名.pages.dev。
"域名商"和"DNS 托管商"可以不是同一家。 你在 A 家买域名，但可以把它的 NS（第 3 章）改成 B 家（如 Cloudflare），让 B 家负责解析——很多人这么做，因为 Cloudflare 的 DNS 又快又免费。买域名的地方 ≠ 一定在那里管解析。
验证方法 · 确认域名真的接上了
  1. 配完记录，等一会儿（TTL 传播），nslookup www.你的域名.com，看到它解析到 github.io / pages.dev 或对应 IP。
  2. 浏览器打开 https://www.你的域名.com，能看到你的网站 = 接通了。
  3. 对照第 4 章：现在你自己的域名，也要走一遍那趟"根→顶级域→权威"的接力，只不过最后一棒返回的是你配的记录。
验证到了什么：DNS 记录一配、传播一到，自定义域名就能打开你的静态站——两篇教程在这里合体。
安全 · 地址栏那把小锁

第 7 章：那把 🔒 是什么？（HTTPS / SSL 证书）

第 4 章第 7 步的展开，大白话版

http 是"明文通信"，中间任何人（同一个 WiFi、你的运营商）都能偷看甚至篡改你传的内容。https 里多的那个 s = secure，就是给通信加了密。

它靠"证书"实现，大白话三件事：
① 加密：内容变乱码，中间人偷看到的是天书。
② 验明正身：证书由可信的证书颁发机构 CA签发，证明"你连的确实是这个域名的真服务器，不是钓鱼假冒的"。
③ 防篡改：内容被中途改动能被发现。
地址栏的 🔒，就是浏览器在说"这条连接已加密、对方身份已验证"。
好消息：证书现在免费且自动。 过去要花钱买证书，如今 GitHub Pages、Cloudflare Pages 都会自动帮你申请并续期免费证书（用 Let's Encrypt 这类免费 CA）。你几乎不用管——第 5 章绑好域名，勾一下"强制 HTTPS"，锁就来了。
验证方法 · 检查证书的真伪和信息
  1. 打开任意 https 网站，点地址栏那把 🔒 → "证书/连接安全" → 能看到证书颁给了哪个域名、由哪个 CA 签发、有效期。
  2. 故意访问一个证书有问题的站（或把系统时间调到很久以后），浏览器会弹红色警告——这就是"验明正身"在起作用。
  3. 对照第 4 章第 7 步：这把锁就是那次 TLS 握手的成果。
验证到了什么：HTTPS 的锁不是装饰，点开能看到真实证书；它保证加密+对方身份可信。
收尾 · 排错与冷知识

第 8 章：常见困惑排错 + 几个冷知识

把零散的疑问一次收干净
困惑 / 现象大白话解释
改了 DNS 没生效缓存没过期（第 5 章 TTL）。等传播，或清本地缓存 ipconfig /flushdns。
域名突然打不开了先查是不是忘了续费到期（第 2 章）；再查 DNS 记录是否被误删。
某些网络能开、某些不能可能是 DNS 缓存不一致，或被网络屏蔽/污染（部分地区对某些域名的解析被干扰）。换 DNS（1.1.1.1）有时能缓解。
www 能开、不带 www 打不开（或反过来）两者是不同记录，要各配一条（或设置一个跳转到另一个）。
域名和网址、URL 什么关系域名是网址里"定位服务器"的那一段；URL = 协议 + 域名 + 端口 + 路径 + 参数，域名只是其中一块。
hosts 文件是什么你电脑里一个本地小通讯录，优先级比 DNS 高。可手动写"某域名→某 IP"用于测试（第 4 章第 1 步会先查它）。
安全提醒：域名是你的重要资产。开自动续费、给注册商账号开两步验证、别在不明网站输入域名管理密码。域名被盗或过期被抢，网站和邮箱可能一起丢。
验证方法 · hosts 优先级小实验（可选）
  1. （了解即可，改前备份）在 hosts 文件加一行 127.0.0.1 example.com，保存后 ping example.com，会指向 127.0.0.1——证明 hosts 比 DNS 先被查。
  2. 实验完务必删掉那行，否则你真访问不了那个域名了。
验证到了什么：第 4 章"先查本地"不是空话，hosts 就是那个最优先的本地小本本。

把第 4 章的接力，用命令亲手跑一遍

亲手追踪 DNS 接力（第 4 章第 3–5 步）

# 逐级追踪：根 → 顶级域 → 权威，一行行打印
dig +trace example.com

# 只看最终结果 + TTL
dig example.com

# Windows 没有 dig 时用 nslookup
nslookup example.com
nslookup -type=cname www.某域名.com
nslookup -type=ns example.com     # 看权威服务器是谁

看"连接"部分（第 4 章第 6–8 步）

# 浏览器 F12 → Network → 点第一个请求 → Timing 面板
# 能看到 DNS / TCP(Initial connection) / SSL(TLS) / Waiting / Download

# 命令行看连接细节
curl -v https://example.com     # -v 打印握手、证书、响应头
ping example.com                # 看域名→IP + 连通性
