最原始层 · 一切的地基

第 0 层：数与运算的本质

主线不是"介绍运算"，而是——每一种数，都是被某个"算不下去"的问题逼出来的

课本会直接把负数、分数一股脑塞给你，好像它们天经地义。但真实的数学史是：人类先只会数数，后来一次次撞到"这套数不够用"的墙，才被逼着发明新数。看懂这条"被逼扩张"的主线，你就真的知其所以然了。

① 最开始：只有"数数"——数 = 数量的标签

远古人要记"我有几只羊"，于是把"5 只羊"和"5 根手指"里共同的那个东西抽出来，贴个标签叫 5。数不是实物，是"数量"这个抽象——同一个 5，能贴给羊、人、天数。这一步抽象，就是一切数学的起点。

加法是最原始的运算 = 合并（两堆并一堆）。减法是它的逆 = "拿走 / 还差多少"。

② 第一次撞墙："3 减 5" 不够减 → 逼出 0 和负数

只用数数的数（1,2,3…），3−5 是做不下去的——你没法从 3 只羊里拿走 5 只。但现实里"欠债 2 只""亏了 2 块"明明存在。于是人类被逼着造出 负数（反方向的数）和 0（什么都没有也得有个数表示）。

知所以然：负数的存在理由，就一句话——为了让减法"永远做得下去"。
历史张力：中国《九章算术》两千年前就用正负数记盈亏；而欧洲到 17 世纪还骂负数是"荒谬的数"。课本一句"数轴向左"把这几百年的挣扎全抹平了。
③ 偷懒与再撞墙：乘法 = 重复加；"3 个饼分 2 人" → 逼出分数

乘法不是新东西，是加法的偷懒：3×4 就是 4+4+4。除法是乘法的逆，也是"平均分"。

可 3÷2 又做不下去了——整数里没有哪个数乘 2 等于 3。但"3 个饼分 2 人，每人一个半"现实存在。于是被逼出 分数 / 小数 = 把"1"切开。

看出规律没：负数是为了"减法封闭"，分数是为了"除法封闭"。每一次数系扩张，都是为了让某个运算"不再卡壳"。
④ 通往初中的钩子：正方形对角线"量不尽" → 逼出无理数

边长为 1 的正方形，对角线长是 √2。毕达哥拉斯学派本以为"任何长度都能用分数表示"，结果发现 √2 写不成任何分数（无限不循环）——这直接引爆了古希腊的数学信仰危机。于是分数（有理数）也不够用了，被逼出 无理数。（严格的"实数"要到第 1 层以后才收拾干净。）

再往后：x²=−1 在实数里无解 → 又逼出"虚数"。可见这条"被逼扩张"的线，会一路延伸下去。

⑤ 一个贯穿全教程的用法：比例

比例就是除法的一种用法（"谁是谁的几倍""占多少"）。别小看它——后面的 概率、期望、学习率本质全是比例。依赖：除法

数数(ℕ) —"减不动"→ 0 与负数(ℤ) —"分不匀"→ 分数(ℚ) —"量不尽"→ 无理数→实数(ℝ) —"开不出"→ 虚数(ℂ)
练习 · 第 0 层（做完再往上爬）
手算 不用"负数"这个词，只用"欠债"解释 3 − 5 = −2 是什么意思；再算 (−3) + 5 和 (−3) × 4。
3−5：你有 3 块却要还 5 块，还完还欠 2 块 → 欠债 2 = −2。(−3)+5：先欠 3 块，又拿到 5 块，还清后剩 2 块 = +2。(−3)×4："欠 3 块"这件事发生 4 次 = 欠 12 块 = −12。
关键：负数不是"神秘符号"，就是带方向的数量。
反问 既然"乘法只是重复加法的偷懒"，那 3 × 0.5 该怎么理解？"重复加 0.5 次"说得通吗？
"重复加半次"确实讲不通——这正说明：把新概念硬套旧直觉，迟早会崩。3×0.5 要换个角度："取 3 的一半" = 1.5，即乘法从"重复加"升级成了"缩放"（乘 0.5 = 缩到一半，乘 2 = 放大一倍）。
这个"缩放"直觉，正是第 2 层向量数乘、第 6 层学习率×梯度的种子。知所以然的意义就在这：知道一个直觉在哪失效、被什么取代。
思考 用"被逼扩张"的逻辑猜一下：为什么人类需要 0 这个数？如果没有 0，会有什么算不下去？
至少两处会卡：① 3−3 没有结果可写（"什么都不剩"也得有个数表示）；② 记数时没法区分 25 和 205（0 占位）。所以 0 是被"减法要封闭"和"位值记数"两件事一起逼出来的。
冷知识：0 被当成"一个正经的数"接受得非常晚（古希腊甚至没有 0），这也印证了本层主线——越是看起来天经地义的东西，历史上越是挣扎着才被逼出来。
本层顿悟：每一种数都不是天上掉的，是某个"算不下去"的问题逼出来的；而乘除只是加减的偷懒。记住这条"被逼扩张"的主线，你就有了"知所以然"的钥匙——上面每一层，我们都会先问"上一套在哪卡住了"。
第一次抽象 · 从"算一个数"到"研究一种关系"

第 1 层：代数与函数

上一层卡在哪 → 只会算"具体的数"，没法表达"任意数都成立的规律"，也没法"倒推未知"
① 什么问题逼出"用字母"？——想表达"任意"和"未知"

算术只能算具体的数：3+5=8。但人类想说两种它说不出的话：
① 规律："任何数加 0 还是它自己"——这个"任何数"怎么写？
② 未知："我不知道买了几个，但知道每个 3 元、总共花了 21 元"——那个"几个"怎么算？
于是给"任意/未知的数"一个把手：字母 x。3x=21 一解，倒推出 x=7。代数 = 给还不知道的数一个名字，然后照样对它做运算。依赖：四则运算

② 什么问题逼出"函数"？——科学要描述"一个量随另一个量怎么变"

物理、天文要说"路程随时间怎么变""温度随高度怎么变"。这不是算某一个数，而是描述一整套对应关系：给个时间，就有个路程。这套"输入→输出"的机器，就叫 函数 y=f(x)。★ 整个 AI 模型，就是一个巨大的 f：喂一串数进去，吐一串数出来。依赖：变量

y = w·x + b　（最简单的函数：一条直线。w 控制多陡，b 控制上下平移）

★ 记死这条直线——它就是"一个神经元"的骨架。AI 的几十亿参数，本质就是无数个 w 和 b。

③ 什么问题逼出"对数"？——把"大数相乘"变成"相加"来手算

指数好懂：重复乘（2³=2×2×2），描述"翻倍增长"（利息、繁殖）。依赖：乘法

对数才是重点，而它的"所以然"极其实在：16 世纪天文航海要把一堆大数相乘，手算能算哭。纳皮尔发明对数，把 乘法变成加法（log(a×b)=log a+log b），大大简化计算——这是对数被逼出来的真实原因。它的含义是"翻了几次"（log₂8=3）。★ 损失函数里到处是 log，就是因为它能把"翻倍的稀有度"压成"可相加的数量级"（第 5 层用得上）。依赖：指数

"想表达任意/未知" → 字母 x → "想描述量与量的关系" → 函数 f(x) → 最简单的 f → 直线 wx+b（神经元骨架）
练习 · 第 1 层
手算 某商品买 x 个、每个 3 元、又付了 5 元包装费，总价 y。写出 y 和 x 的函数；再求总价 20 元时买了几个。
y = 3x + 5（正是 wx+b，这里 w=3、b=5）。总价 20：20=3x+5 → x=5。
体会：w=3 是"每多买一个多花多少"（斜率），b=5 是"一个都不买也要付的底价"（截距）——这两个词第 3 层会变成"梯度"和"偏置"。
反问 为什么说"AI 模型就是一个函数 f"？它和 y=3x+5 到底是不是一回事？
是一回事，只是规模天差地别。y=3x+5 是 1 个输入、2 个参数的迷你函数；GPT 是"几千个数进 → 几千个数出、里面几千亿个 w 和 b"的巨型函数。结构一样：输入→（一堆 wx+b 和掰弯）→输出。所以你只要真懂 wx+b，就抓住了 AI 的骨架。
思考 对数把乘法变成加法（log(ab)=log a+log b）。猜猜：为什么"把乘变加"在计算机/AI 里特别值钱？
两个原因：① 数值稳定——一堆很小的概率连乘（如 0.001×0.002×…）会小到计算机存不下（下溢），取 log 变成相加就稳了，所以 AI 算概率几乎全在"对数空间"里做。② 把"指数级差距"压平成"线性差距"，好比较、好求导。这正是第 5 层"信息量=−log(概率)"的伏笔。
本层顿悟：代数是给"未知/任意"一个把手，函数是把"关系"当成研究对象；最简单的函数 wx+b 就是神经元。你已经握住了 AI 的骨架。
AI 的骨架 · 一个操作撑起半个 AI

第 2 层：线性代数（向量 · 点积 · 矩阵乘）

上一层卡在哪 → 函数只处理"一个数进、一个数出"，可现实里的东西往往是"一组数"
① 什么问题逼出"向量"？——很多东西天生就是"一串数"

一个数描述不了的东西太多了：力有"大小+方向"、一个学生有"语数英三科分"、一个词要用一串数来编码。把一串数当成一个整体来算，就是 向量 [1.2, −0.3, 0.8]。它有两副面孔：一串特征（一个词的编码），或空间里的一支箭头。依赖：数

向量加法=两支箭头首尾相接（合成两个力）；数乘=把箭头整体拉长缩短（就是第 1 层练习里的"缩放"直觉）。

② 什么问题逼出"点积"？——想量"两个方向像不像"

你有两个向量，想问"它们方向一致吗、有多像？"于是定义 点积：对应位置相乘、再全部相加，得一个数。

[a, b] · [c, d] = a·c + b·d　（对应相乘，再相加）

它的几何含义：两支箭头方向越一致，点积越大；垂直时为 0；相反时为负。所以点积 = 相似度打分。★ 这就是注意力的核心——"这个词该关注那个词吗"，就用它俩向量的点积来打分。依赖：乘法、加法

③ 什么问题逼出"矩阵"？——想一次性对一整批向量做同样的变换

你不想一个一个地算，想"把一整层神经元一次算完""把整幅图一次旋转"。把一堆数排成表，就是 矩阵；它的真身是"对空间的一个动作"（旋转/拉伸/投影），不是死数表。

矩阵 × 向量 = 一次做很多个点积：输出的每个数，都是矩阵某一行和输入向量的点积。★★ 神经网络"一层"的计算，就是一次矩阵乘——把上一层的向量，用一堆权重做一批点积，变成下一层的向量。依赖：点积

shape（形状）=行数×列数。AI 报错一大半是"shape 对不上"（前一个的列数 ≠ 后一个的行数就没法乘），所以要会数。

"东西是一串数" → 向量 → "想量方向像不像" → 点积=相似度 → "想一次变换一批" → 矩阵乘 = 神经网络一层
练习 · 第 2 层
手算 求 [2, 1]·[3, 4] 和 [1, 0]·[0, 1]，并说说后者为什么是 0。
[2,1]·[3,4]=2×3+1×4=10。[1,0]·[0,1]=1×0+0×1=0。后者为 0 是因为这两支箭头互相垂直（一个朝右、一个朝上），"方向毫无重合" → 相似度 0。点积=0 记成"正交/不相关"，后面很有用。
反问 都说"神经网络一层就是一次矩阵乘"，可矩阵乘不就是一堆乘加吗？凭什么它能"学复杂东西"？
单靠矩阵乘确实不行——矩阵乘是"线性"的，一层接一层叠起来还是等价于一条直线，学不了弯弯绕绕。所以每层矩阵乘后面要接一个"掰弯"的激活函数（第 7 层）。矩阵乘负责"批量线性组合"，激活负责"掰弯"，两者交替才有威力。这道反问正好逼出第 7 层的关键。
思考 词向量让"语义相近的词，向量也相近"。若 国王、女王、男人、女人 各是一个向量，你觉得 国王−男人+女人 大概会落在谁附近？为什么？
落在 女王 附近。因为"国王→男人"这段向量差，大致等于"从王室里抽掉男性属性"；再加"女人"就补上女性属性 → 得到"女王"。这说明向量的加减真能对应"语义的加减"，是词向量最惊艳的性质。
（注：你那份 Transformer 文档里把这个经典例子写成了"皇冠−男人+女人"，其实原版是"国王(king)"，别记错。）
本层顿悟：向量=一串数，点积=相似度，矩阵乘=神经网络一层。就这三样，撑起半个 AI；注意力、每一层的计算，全落在这。
学习的引擎 · 回答"旋钮往哪拧"

第 3 层：微积分（导数 · 链式法则 · 梯度）

上一层卡在哪 → 会用矩阵乘搭出函数了，但"怎么调 w、b 才能让它吐得更对"还不知道
① 什么问题逼出"导数"？——想知道"此刻变化有多快"

17 世纪牛顿研究运动（"这一瞬间速度多少"）、莱布尼茨研究曲线切线，都撞到同一个需求：某一点上，x 动一丁点，y 变多少？ 先看"一段"的平均变化：斜率 = Δy/Δx（就是除法）。再把这段缩到无穷小，得到"就这一刻"的变化率——导数。依赖：斜率←除法

★ 对 AI 来说，导数回答的正是那句核心问题："这个旋钮往上拧一点，误差是变大还是变小、变多少？" 知道了这个，就知道该往哪拧。

顺带印证第 0 层讲的历史张力：牛顿/莱布尼茨 1680 年代就在用微积分，但"无穷小到底是不是 0"含糊不清，被贝克莱主教讥讽为"逝去量的幽灵"。直到 1820s 柯西、魏尔斯特拉斯用极限把它讲严格，中间整整两百年"先算得对、后证得了"。
② 什么问题逼出"链式法则"？——一环套一环的变化怎么算

神经网络是"函数套函数套函数"：输入经第 1 层变成 u，u 经第 2 层变成 v……最后算出误差。要问"最前面的旋钮动一下，最后的误差变多少"，就得一环环把变化率乘起来：

dy/dx = (dy/du) × (du/dx)　（y 随 u 变，u 随 x 变 → 两段变化率相乘）

★★ 这一条，就是反向传播的全部数学：误差从最后一层，顺着链式法则一环环乘回第一层，算出每个旋钮"该为这次错误负多少责"。你那份 Transformer 文档里神乎其神的"反向传播"，拆到底就是这个乘法链。依赖：导数

③ 从"一个旋钮"到"几十亿旋钮"：偏导与梯度

模型有几十亿个旋钮。偏导数 = 固定其它、只动一个旋钮看误差怎么变（几十亿个旋钮就有几十亿个偏导）。把它们全部打包成一个向量，就是 梯度。依赖：偏导、向量

梯度指向"误差上升最快"的方向 → 反过来走，就是误差下降最快的方向。训练每一步就干一件事：算出梯度，往它的反方向挪一小步（下一层细讲）。

"想知道此刻变多快" → 导数 → "函数套函数" → 链式法则 = 反向传播 → "几十亿旋钮" → 梯度 = 最陡下坡的指南针
练习 · 第 3 层
手算 f(x)=x²，用 Δy/Δx 估计它在 x=3 处的变化率：取 Δx=0.001 算一遍，看它接近多少。
f(3)=9，f(3.001)=9.006001。Δy/Δx=(9.006001−9)/0.001=6.001 ≈ 6。
（x² 的导数是 2x，在 x=3 处正是 6。）体会：把 Δx 缩得越小，这个比值越贴近"瞬时"的 6——这就是导数的"极限"含义。
反问 为什么反向传播非要"从后往前"算？从前往后一层层算梯度不行吗？
数学上都能算，但从后往前极其省力。误差在最后一层，链式法则是把"后面的变化率"乘给"前面的"；从后往前走，每一层能把已算好的结果直接传给下一层复用（一次扫完就得到所有梯度）。从前往后则要为每个旋钮重复算整条链，浪费到不可行。所以叫"反向传播"——不是必须，而是因为快得多。
思考 梯度指向"上升最快"的方向。为什么训练要往反方向走？如果沿梯度正方向走会怎样？
训练目标是让误差（损失）变小，而梯度指向误差变大最快的方向，所以要往反方向走才是"下山"。若沿正方向走 = 拼命"上山"，损失越来越大，模型越练越蠢。
这也解释了那行核心公式里的减号：新旋钮 = 旧旋钮 − 学习率×梯度（第 6 层）。
本层顿悟：反向传播不神秘，就是链式法则从后往前批量算梯度；训练每一步 = "算梯度 → 往反方向挪一小步"。至此，AI 的"学习引擎"你已看穿。
不确定性的语言 · 模型不给答案，给概率

第 4 层：概率与统计（分布 · 期望 · softmax）

上一层卡在哪 → 能让模型"算出一个确定的数"了，但现实是不确定的：同样的开头，下一个词有很多可能
① 什么问题逼出"概率"？——想给"可能性"一个数

17 世纪贵族赌骰子，找帕斯卡、费马算"这局我平均能赢多少、该怎么分赌注"。为了回答，人类被逼着给"可能性"配一个数：概率 = 0 到 1 之间的一个数，0=不可能、1=必然，本质就是"占比"（掷骰子出 6 的概率 = 1/6）。依赖：比例

★ 对 AI 极其关键：模型不该吐"唯一确定答案"。"今天天气很___"后面填"好/热/冷/糟"都合理，模型该给的是每个词多大可能——一张 概率分布表，而不是一个词。

② 什么问题逼出"期望"？——想知道"平均而言得多少"

赌局有多个结果、各有概率，想问"长期玩下去平均每把赢多少"。答案是 期望 = 加权平均：每个结果 × 它的概率，再全部相加。依赖：乘法、加法

★ AI 的"损失"就是误差的期望——不是看某一条数据错多少，而是看"平均而言错多少"。另一个量 方差 = 波动有多大（离平均多散）；★ 权重初始化、归一化，本质都在控制方差，别让信号越传越炸或越传越没。

③ 什么问题逼出"条件概率"？——语言模型的真身

条件概率 P(A|B) = "已经知道 B 发生了，A 的概率是多少"（下雨天带伞的概率，比晴天高）。★★ 语言模型的本质，一句话就是它：

P(下一个词 │ 前面所有词)　（"今天天气很" 已知 → "好"的概率多大？"热"呢？）

整个 GPT，做的就是不停算这个条件概率、然后按概率挑下一个词。依赖：概率

④ 什么问题逼出"softmax"？——把一堆"分数"变成"概率"

模型内部一通矩阵乘（第 2 层）算出来的，是一串没头没脑的分数（叫 logits，可正可负、可大可小，比如 [2, 1, 0]）。可"概率"必须满足两条：都非负、加起来等于 1。分数不满足，怎么办？softmax 两步搞定：

① 各取指数（变正、拉开差距）：e² , e¹ , e⁰ = 7.39 , 2.72 , 1.00 ② 除以总和（凑成 1）：/11.11 → 0.665 , 0.245 , 0.090　←加起来=1，成了概率

★ 模型输出层就是它。用指数是因为它永远为正、还能把"分数的小差距"放大成"概率的大差距"（2 比 1 只高 1 分，概率却 0.665 比 0.245 高一大截）。依赖：指数、除法

连回第 1 层：为什么偏用"指数"而不是别的变正办法？因为指数和第 5 层的 log 是逆运算，一对上，损失函数的求导会变得异常干净——这不是巧合，是精心设计。
⑤ 训练目标的本质：极大似然

那"训得好"到底是什么标准？极大似然：调旋钮，让模型给真实出现过的数据打的概率尽量大。训练语料里"今天天气很好"出现了，就调参数让 P(好│今天天气很) 变高。训练 = 让真实答案的概率最大化。依赖：条件概率

"想量可能性" → 概率 → "平均得多少" → 期望=损失 → "给定前文猜下词" → 条件概率=语言模型 → "分数变概率" → softmax = 输出层
练习 · 第 4 层
手算 对分数 [1, 0, 0] 做 softmax（e¹≈2.72, e⁰=1），求三个概率；并说说和 [2,1,0] 那个例子比，谁"更拿不定主意"。
exp 后 [2.72, 1, 1]，总和 4.72 → 概率 [0.576, 0.212, 0.212]。
它比 [2,1,0]→[0.665,0.245,0.09] 更拿不定主意：最高概率只有 0.576（vs 0.665），且后两个并列。分数拉得越开，softmax 越"自信"；分数越接近，输出越"平均、越犹豫"——这正是第 5 层"熵=不确定性"的前奏。
反问 既然要"分数变概率"，为什么不直接"每个分数 ÷ 总分"，非要先取指数这么麻烦？
"÷总分"有两个死穴：① 分数可能是负数（如 −3），除出来会是负概率，非法；② 差距被压得太平，模型没法表达"我很确定是它"。指数先把一切变正、又把差距按指数放大，两个问题一起解决。所以 softmax 的"麻烦"是被这两个硬约束逼出来的，不是故弄玄虚。
思考 "训练=让真实答案概率最大"。若某句训练数据里下一个词是"好"，模型当前给"好"的概率只有 0.05，你觉得接下来梯度会把这个概率往哪推？这跟第 3 层的"梯度"怎么接上？
往上推——目标是让 P(好) 变大。具体做法：定义一个"越不对越大"的损失（第 5 层的交叉熵 −log(0.05)，很大），对它求梯度（第 3 层），梯度会告诉每个旋钮"往哪拧能让 P(好) 升、损失降"，再往反方向挪一步（第 6 层）。你看，概率(4层)→损失(5层)→梯度(3层)→更新(6层)已经串起来了，第 7 层就是把它们拼成完整训练循环。
本层顿悟：模型不输出答案，输出概率分布（靠 softmax）；训练目标 = 让真实答案的概率尽量大（极大似然）。下一层就把"概率错多少"变成一个能求导的损失数。
损失函数从哪来 · 把"对不对"变成一个能求导的数

第 5 层：信息论（信息量 · 熵 · 交叉熵）

上一层卡在哪 → 有了概率分布，也知道"要让真实答案概率变大"，但"错多少"还不是一个具体的数
① 什么问题逼出"信息量"？——想量"一条消息值多少"

1948 年香农研究通信：一条消息该用几个比特发、怎么编码最省？他要给"信息"一个度量。关键直觉：越不可能发生的事，一旦发生，信息量越大。"太阳从东边升"你早知道，信息量≈0；"某号码中了头奖"信息量巨大。于是定义：

信息量 = −log(概率)　（概率越小 → −log 越大 → 越"意外"、信息越多）

为什么用 log？两个理由都在前面铺过：① 让独立事件的信息可以相加（log 把"概率连乘"变成"信息相加"，连回第 1 层）；② 把"指数级的稀有度"压成"线性的数量级"，好算好比。依赖：对数、概率

② 什么问题逼出"熵"？——一整个分布"平均有多不确定"

单个事件有信息量，那一整张概率分布平均有多少信息 / 多不确定？把每个结果的信息量，按它的概率加权平均（就是第 4 层的期望），得到 熵。依赖：信息量、期望

确定的事熵=0（骰子灌了铅必出 6，毫无悬念）；越"五五开、拿不定"熵越大（公平硬币熵最大）。熵 = 不确定性的度量——正好接上第 4 层练习里"softmax 越平均越犹豫"那句话。

③ 什么问题逼出"交叉熵"？——它就是 AI 的损失函数

现在到重点。有两张分布：真实分布 P（真答案是"好"，那 P 在"好"上=1、其余=0）和模型以为的分布 Q（softmax 吐出来的那串概率）。问：用模型的 Q 去给真实的 P 编码，要付多少代价？ 这个代价就是 交叉熵——Q 越贴近 P，代价越小；越偏离，代价越大。

因为真答案是"one-hot"（只有正确那项=1，其余=0），求和一化简，交叉熵只剩正确类那一项：

交叉熵损失 = −log( 模型给正确答案的概率 )　←整个 AI 的损失函数，就长这样

★★ 真答案是"好"、模型只给"好"打了 0.05 → 损失 −log(0.05) 很大，狠罚；给了 0.9 → −log(0.9) 很小，几乎不罚。它天然可求导（log 光滑），于是第 3 层的梯度、第 6 层的下降就能接手了。依赖：熵、softmax

为什么 softmax 和交叉熵是"绝配"？ softmax 里有指数、交叉熵里有 log，两者是逆运算，一组合，求导结果简洁到惊人：梯度 = 模型概率 − 真实概率（"猜的减真的"）。这就是为什么它俩几乎总是成对出现——是数学上刻意凑的一对。
④ 顺带认识：KL 散度

KL 散度 = 交叉熵 − 真实分布自己的熵，衡量"模型分布 Q 离真实分布 P 有多远"（越远越大，完全一致时=0）。训练最小化交叉熵，本质就是把 Q 往 P 拉近。依赖：交叉熵

"想量一条消息值多少" → 信息量=−log(p) → "整个分布平均多不确定" → 熵 → "用模型分布编码真相的代价" → 交叉熵 = 损失函数
纠正你那份 Transformer 文档：它把交叉熵说成"两个分布做减法"、"只惩罚米饭那一个词"——都不对。交叉熵是取 −log（不是减法）；而且反向传播时（靠 softmax+交叉熵那个"猜的减真的"梯度）会把正确词概率往上推、所有错词往下压，不是只盯某一个词。

练习 · 第 5 层
手算 用自然对数，比较模型给正确答案打 0.05 和打 0.8 时的交叉熵损失（ln0.05≈−3.00，ln0.8≈−0.22），谁被罚得狠？
−ln(0.05)=3.00，−ln(0.8)=0.22。打 0.05 的损失是 3.00，是打 0.8（0.22）的十几倍。模型给正确答案的概率越低，损失呈"越来越陡"地暴涨（概率趋近 0 时损失趋近无穷）——这就是交叉熵"逼模型别对正确答案太没信心"的机制。
反问 交叉熵损失只写了"正确答案那一项"，那模型给错误答案分了多少概率，难道完全不管？
直接看损失公式确实只有正确项；但错误项被 softmax 间接管住了：softmax 要求所有概率加起来=1，所以"把正确答案概率推高"必然"把错误答案概率挤低"——它们是一根绳上的（第 4 层）。所以不需要在损失里单列错误项，压正确项就自动压了所有错误项。这也印证了上面纠错：不是"只惩罚一个词"。
思考 熵=不确定性。训练初期模型瞎猜（输出接近均匀），训练后期越来越自信。那模型输出的熵大概怎么变？为什么"熵压得太低"反而可能是坏事？
熵会从高（初期均匀、极不确定）逐渐降低（后期集中、有把握）。但压得太低=过度自信：模型对每个答案都给近乎 1 的概率，一旦遇到没见过的输入就会"自信地错"，而且泛化差（过拟合的信号之一）。所以工程上常用 label smoothing（把真答案的 1 稍微降到 ~0.9）故意留一点熵，别让模型太飘。你文档里"softmax 永远到不了 100%"其实是件好事——它天然留了一丝不确定。
本层顿悟：交叉熵损失 = −log(模型给正确答案的概率)——概率越低罚越狠、天然可求导，而且和 softmax 是求导绝配（梯度=猜的减真的）。到这，"错多少"终于变成了一个能交给梯度下降的数。
怎么调到最好 · 训练的心脏

第 6 层：优化（梯度下降 · SGD · 动量 · Adam）

有了"损失"(第5层)和"梯度"(第3层)，这层讲怎么一步步把损失调到最小
梯度下降
= 沿梯度反方向走一小步：新旋钮 = 旧旋钮 − 学习率 × 梯度。★ 这一行就是训练的心脏。依赖：梯度
学习率
= 每步迈多大。太大跨过最低点甚至飞出去，太小走到天荒地老。它是"比例"，在优化器里、不在模型里。依赖：比例
SGD
= 随机梯度下降：抽一小批数据估计梯度，快且带噪声（噪声还能帮忙逃出小坑）。依赖：梯度下降、期望
动量
= 给下山加惯性：把过去几步方向做加权平均，冲过小坑、加速直道。依赖：移动平均
Adam
= 每个旋钮有自己的步长：一阶矩(方向惯性) + 二阶矩(最近抖得凶就自动减速)。依赖：动量、方差
动画 · 梯度下降"下山"（拖学习率滑块，看它是稳稳到谷底、还是飞出去）
小球在"损失山谷"里。每走一步 = x ← x − 学习率 × 斜率。试试把学习率拉到 0.9 以上，看它怎么"跨过谷底反复横跳甚至飞走"。
纠个常见错：Adam 的二阶矩是"梯度平方的移动平均"（谁最近抖得凶就给谁减速），不是你文档里说的"历史加速度"，Adam 也和物理"动量定理"无关（它叫自适应矩估计）。
本层顿悟：训练 = 反复执行「算损失 → 反向传播求梯度 → 旋钮 −= 学习率×梯度」；Adam 只是让这一步更聪明。
合流① · 全是旧零件，没有新数学

第 7 层：看懂一个神经网络

把前 6 层拼起来——你会发现"训练神经网络"没有一个新数学
一个神经元
= 激活(w·x + b)：直线(第1层) + 一个掰弯。依赖：wx+b
激活函数
= 给直线掰个弯。没有它，多少层叠起来还是一条直线，学不了复杂东西。
前向传播
= 一连串矩阵乘 + 激活，最后 softmax 出概率。依赖：矩阵乘、softmax
反向传播
= 链式法则从输出层求梯度回到输入层。依赖：链式法则
参数更新
= 梯度下降 / Adam，每个 w、b 减去学习率×自己的梯度。依赖：梯度下降
本层顿悟：训练神经网络 = 前向(矩阵乘) → 损失(交叉熵) → 反向(链式法则) → 更新(梯度下降)，循环。全是第 0–6 层的零件。

第 8 层：看懂 Transformer

把文档里每个数学符号，用前面学的东西逐一拆开
词向量
= 把"字"变成一串数，语义近的向量也近。依赖：向量
Q、K、V
= 对词向量各乘一个矩阵得到的三份新向量（查询/被查/内容）。依赖：矩阵乘
注意力打分
= Q·K 点积：两个词相关不相关，用点积量相似度。依赖：点积
÷ √dₖ
= 缩放，防点积太大 → softmax 饱和 → 梯度变小学不动（是防梯度消失；文档里一处说成"防爆炸"是反的）。
softmax(打分)
= 把相关度变成注意力权重（加起来=1）。依赖：softmax
加权求和 V
= 按注意力权重把各词内容混合（权重×向量再相加）。依赖：数乘、向量加法
多头
= 同时开好几套 Q/K/V 看不同角度，再拼起来。
